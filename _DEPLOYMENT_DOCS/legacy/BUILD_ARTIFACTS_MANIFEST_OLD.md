# EUSAI Hub: Build Artifacts & Deployment Manifest

This document serves as the absolute source of truth for locating your compiled production artifacts after every successful build, and outlines the automation capabilities of your deployment pipeline.

## 1. Artifact Locations

Whenever you run the build commands (e.g., `flutter build apk --release`, `flutter build windows --release`), the resulting files are placed deep inside the `build` directory. 

Here are the exact absolute paths:

### Android
*   **Direct Install (APK):** 
    `d:\dev\eusai_crm\eusai_messenger_app\build\app\outputs\flutter-apk\app-release.apk`
    *(Use this for direct side-loading to operative devices).*
*   **Play Store Upload (AAB):** 
    `d:\dev\eusai_crm\eusai_messenger_app\build\app\outputs\bundle\release\app-release.aab`
    *(Use this when uploading to the Google Play Console).*

### Windows
*   **Raw Executable (EXE):** 
    `d:\dev\eusai_crm\eusai_messenger_app\build\windows\x64\runner\Release\eusai_hub.exe`
    *(This is the raw app, but it requires the `data` folder and `.dll` files next to it to run).*
*   **Production Installer (Setup EXE):** 
    `d:\dev\eusai_crm\eusai_messenger_app\build\windows\installer\EUSAI_Hub_Setup.exe`
    *(This is generated by running your Inno Setup `.iss` script. This is the file you distribute to operatives).*

### Apple Ecosystem (When built on a Mac)
*   **iOS Install (IPA):** 
    `build/ios/ipa/eusai_hub.ipa`
    *(Upload this via Transporter to App Store Connect).*
*   **macOS App (APP):** 
    `build/macos/Build/Products/Release/eusai_hub.app`
    *(Convert this into a `.dmg` using Disk Utility before distribution).*

## 2. The EC2 Automation Pipeline

Your current `publish-hub.ps1` script is the bridge between your local Flutter builds and your automated EC2 Web deployment.

### How it works:
1. **The PowerShell Script:** When you run `publish-hub.ps1`, it automatically grabs the `app-release.apk` and the `EUSAI_Hub_Setup.exe` and copies them directly into your Next.js CRM's `public/downloads` directory. It also creates a secure `.zip` of the Windows installer.
2. **The EC2 Push:** Because these files are now inside your CRM's `public/downloads` folder, **yes, they are fully automated for EC2**. The next time you commit and push your web project (or run your EC2 deployment pipeline), those new `.apk` and `.exe` files are automatically synced to the live server.
3. **The Operative Experience:** Your operatives can then visit `https://your-crm-url.com/downloads/eusai_hub_android.apk` or `.../EUSAI_Hub_Setup.exe` to instantly download the latest version.

### The Inno Setup Step (Manual Trigger Required)
The only step that is currently **manual** is compiling the Windows Installer using Inno Setup. 
*   After you run `flutter build windows --release`, you **must** open `windows\installer\setup.iss` in the Inno Setup Compiler application and click **"Compile"**. 
*   This reads the `EUSAI_Agreement.txt` and packages the raw `.exe` and `.dll` files into the final `EUSAI_Hub_Setup.exe` installer.
*   Once you click Compile in Inno Setup, you then run `publish-hub.ps1`, and the automation takes over.
